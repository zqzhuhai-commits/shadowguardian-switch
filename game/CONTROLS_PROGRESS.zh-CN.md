# 控制器修复分支（尚未发布）

基线：`8877f2d991ba624fb54cd0f715f642e850b78ad3`。用户反馈 0.2.1 已能进入游戏，但物理控制不完整。本分支不是新的 NSP 或已完成的 0.2.2 发布。

## 已实现的源码变更

| 输入/功能 | 分支行为 |
| --- | --- |
| 左摇杆 / 方向键 | 游戏中驱动原游戏虚拟移动摇杆 |
| 右摇杆 | 游戏中连续拖动自由视角；无需按 A，不在屏幕边缘停止 |
| B | 游戏中跳跃/跑动/攀爬等原游戏情境动作；菜单中返回 |
| A | 游戏中手形图标的交互/拾取；菜单保留原版触摸光标点击 |
| ZL / L | 原游戏瞄准区域 |
| ZR / R | 原游戏射击区域 |
| X | 在武器图标上向右滑动，请求下一把武器；按下、移动、抬起分三个渲染帧发送 |
| + | 暂停/返回；与 − 同按退出 |
| 菜单方向键 | 发送原生方向键事件并保留原触摸光标移动；原菜单是否消费这些键仍待确认 |
| 自动启动 | 去掉启动前等待 A 的测试界面，检查原库和资源后自动初始化 |
| 启动日志 | 游戏端关闭普通日志和 GL 检查，不创建/轮换 debug.log；保留异常处理 |

情境判断使用参考移植的 `GUILevel::s_isGUIVisible` 导出变量；解析失败停止启动，不以猜测的状态分派 B。全程调用原生触摸输入，不写入角色、弹药或武器状态。暂停、失焦和菜单切换会释放已发送的触摸与返回键；按钮保持按住时不会跨状态重复触发。

坐标和相机连续拖动方式参考 MIT 项目 MetalSyntax/Shadow-Guardian-vita，提交 `043e95be90358dfb57061bbc9412f23f6d8af0ad`；许可保留在 `licenses/shadowguardian-vita-MIT.txt`。这些坐标针对原游戏默认触控布局，自定义布局需重新核对。

## 未完成与发布阻塞

- **Y 换弹尚未绑定**。仓库只包含原库哈希和 JNI 导出清单，没有原库或反编译资料；参考移植没有独立换弹绑定。需要核对原库实际换弹入口和状态门控，不能以猜测坐标或强改弹药冒充完成。
- **未隐藏虚拟按钮**。按照“所有按键绑定好后再隐藏”的要求，等换弹、菜单导航和实机操作确认后再隐藏。
- 原生方向键事件是否能导航所有菜单、GUI 状态标志在暂停/过场中的行为、动作坐标与当前存档布局，都需原库核对及 Switch 验证。主机桩测试不能证明这些原生行为。
- 当前环境没有 devkitARM、补丁版 libnx32、Mesa32/miniz，也没有可用的 NSP 私有打包 keyset 或现成构建流水线。因此**未交叉编译、未生成 NSP、未创建正式 Release**。
- 需要提供匹配现有哈希的 `libshadowguardian.so`（不需提交到公共仓库），以及可用的私有构建/打包环境入口。私有 keyset 不得提交到源码仓库。

## 已执行验证

`bash game/tests/run_host.sh` 全部通过（ASan/UBSan，沿用项目关闭 LeakSanitizer 的设置）：

- JNI 初始化顺序/参数及缺失导出失败门控。
- ATC、720p/离屏 GL、音频与 SWP 原有回归测试。
- 新增生产输入模块测试：B 双语境、方向键移动、右摇杆持续旋转越过屏幕边界、逐帧武器滑动、扳机别名合并、状态切换/失焦释放与保持按钮抑制、真实触屏坐标映射、退出组合。
- 原库导入表：214 个非 GL 导入全部绑定，65 个 GL 导入交给运行层。

这些测试以模拟的原生事件接收器检查调用序列，不执行原始游戏。没有宣称新分支通过 Switch 实机测试或完成换弹/屏幕按钮隐藏。
