## 输入映射

| 输入 | 游戏中 | 菜单中 |
| --- | --- | --- |
| 左摇杆 / 方向键 | 移动 | 移动可见光标 |
| 右摇杆 | 持续拖动视角，无需按 A | 移动可见光标 |
| A | 交互、拾取 | 点击光标所在位置 |
| B | 跳跃、跑动、攀爬等情境动作 | 返回 |
| Y | 原地点击武器图标，请求换弹 | 无游戏动作 |
| X | 在武器图标上右滑，请求下一把武器 | 无游戏动作 |
| L / ZL | 瞄准 | 无游戏动作 |
| R / ZR | 射击 | 无游戏动作 |
| + | 暂停 | 返回 |
| + 与 − | 退出 | 退出 |

默认触摸布局基于参考移植的实机坐标；游戏中自定义移动过的按钮布局仍需单独核对。暂停、失焦和操作阶段切换会释放已发送的输入，保持按住的按钮不会跨状态再次触发。

## 原库核对

- `Game::OnKeyPressed`（`0x0bf300`）不会处理 Android 方向键，删除此前无效的菜单方向键注入；菜单由物理按键/摇杆移动可见的触摸光标，A 点击原菜单。
- `Game::IsInActionPhase`（`0x0bf710`）读取 `Game + 0x172`。`GS_GamePlay::SuspendState` / `ResumeState` 置零/置一该字段。B 按此真实状态分派，不再把全局 GUI 可见性当作菜单状态。
- `Game::OnPointerPressed/Released` 将坐标除以窗口宽度/480。800 像素宽度下，武器图标 x=688 变为 412.8，落在原生换弹区间 365..450。X 从 688 滑到 788，归一化增量 60，超过原生切武器阈值 30。
- `PlayerCtrl::Update`（`0x130b24`）仍控制是否启用、角色模式、动作子状态和武器按钮状态。Y 的原生路径在 `0x130e04` 调用玩家的虚函数 `OnReload`；`Player::OnReload` → `Actor::OnReload`（`0x0e14a8`）继续检查武器、备用弹药、满弹匣和换弹状态。没有调用底层 `ReloadWeapon` 直接补充子弹。
- 所有事件仍走原生触摸接口；未修改原库文件、角色状态、弹药数或武器切换逻辑。

## 0.2.3 恢复触屏操作

用户已确认 0.2.2 的视角控制有效，但需要显示触屏按钮来完成躲藏、换弹等操作。0.2.3 完全移除隐藏按钮的 C 绘制包装、ARM 跳板以及虚拟摇杆/按钮计量条的绘制替换，恢复原游戏的按钮、高亮和计量显示。所有触屏事件仍直接送入原生触摸接口，物理输入逻辑未改变。

启动时自动检查并加载游戏，普通启动日志和 GL 调试检查继续关闭；崩溃异常处理保留。
